## いま走っている実験

### E1：冒頭を「直接入り」に（2026-11-13〜、#009 から）

- **仮説：** 離脱が先出し→巻き戻し→シリーズ名カード→本編の切り替わり（5〜10秒）に集中しているのは、巻き戻して仕切り直す構造が「始まり直した」と受け取られ、指が動くため。先出しの一言からそのまま本編へ続ければ、5〜10秒の落ち込みが減る。
- **変えるのは冒頭だけ：** 先出しの1行 → 巻き戻し・暗転・シリーズ名カードをなくし、そのまま本編1行目へ。シリーズ名のネオンはオチの文字にだけ残す。尺（75〜90秒）、説明、声、画、オチは変えない。`variant` は `{"experiment":"E1","opening":"direct","target_seconds":"75-90"}`。
- **対象：** #009〜#011 の3本。対照は #005・#007・#008（従来の冒頭、90秒）と #002・#003（従来の冒頭、60秒）。
- **何を見るか（API の `api-d2`、公開3日後に自動記録）：**
  1. **維持率の5秒→10秒の落ち**（`python tools/analytics.py retention <話数>`）。従来は 0.99〜1.0 → 0.31〜0.54。ここが主指標
  2. 平均視聴率（API平均視聴率%）と視聴あたり再生（尺比%）
  3. 視聴回数が「いつもの範囲」の中か上か（題材でぶれるので副指標）
- **判定（3本の平均）：** 10秒時点の維持率が、従来の #005（0.46）・#007・#008 を明らかに上回れば効いた（目安は0.6以上）。変わらなければ冒頭構造は主因でない → E2（先出しの中身を作り直す）か、題材・サムネ側へ。
- **注意：** n=3で、題材の違いが混ざる。確定ではなく、次の一手を決める材料。
- **取り下げた案：** 尺を65〜70秒に戻す案（同日に一度設定）。API の維持率で、90秒の #005 が60秒の #002・#003 より悪くないと分かったため、尺は変えない。

## 次の候補（E1の結果を見てから1つずつ）

- **E2：先出しの中身を作り直す。** 先出しの一言と画を、より引きの強いものに（維持率が最初の5秒でどう動くかを見て決める）。
- **E3：題材・タイトル・サムネ。** 視聴回数の差（#003が816、#005が192）が維持率で説明できないため、配信の入口（タイトルとサムネ、最初に見せる人たち）の側を疑う。サムネは今、男の顔のアップがほぼ同じ構図で並んでいる。
- **E4：尺を短くする。** 維持率では主因でなかったので優先度は低い。

## 記録のしかた

**自動（2026-11-13〜、認証し直したあと）：** Actions の `metrics`（毎日1回）が、公開から3日たった話の数字を YouTube Analytics API から読み、`metrics.json`（窓 `api-d2`）とこの文書の表を更新する。手元では `python tools/analytics.py check|fetch|retention|auto`。`retention` は維持率の曲線で、冒頭の何秒で落ちるかが分かる。前提は video-publisher の「YouTube認証」でのトークンの権限追加（未実施なら `check` が止まる）。API の日付は太平洋時間の日単位で、Studio の48時間とは一致しないため、窓は別名（`api-d2`）にして混ぜない。API はまだ実機で未検証。

**手入力（Studio の数字を貼る場合）：**

1. 公開48時間後、Studio の動画の「分析」から、視聴回数・総再生時間・フィード経由・視聴を続けた割合・登録者を読む
2. `python tools/metrics.py add 009 --window 48h --views … --hours … --feed … --stayed … --subs …`
3. `python tools/metrics.py table --window 48h --write`（この表を更新）→ commit
- 窓は48hにそろえる。Studio の数字を貼って Claude に頼んでもよい
